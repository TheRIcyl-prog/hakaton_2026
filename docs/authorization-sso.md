# Демо-вход в АРМ координатора

**Назначение.** На показе координатор вводит заранее подготовленные логин и пароль. АРМ открывает дашборд под именем демо-координатора. Изменения из АРМ и мини-ITSM сохраняются в текущем локальном наборе инцидентов, а в журнале виден автор из активной сессии.

**Решение для первого этапа.** Один заранее созданный аккаунт с ролью координатора покрывает основной сценарий. Если на показе нужны два рабочих места с разными авторами, в той же конфигурации задаётся второй аккаунт. Корпоративный SSO и запись в рабочую SimpleOne относятся к следующему этапу.

## 1. Как проходит показ

1. Ведущий открывает дашборд в новом окне браузера. На экране «Вход в АРМ координатора» видны поля «Логин», «Пароль» и кнопка «Войти».
2. Ведущий вводит подготовленные реквизиты. FastAPI сверяет их с демо-конфигурацией, открывает сессию и возвращает профиль. В шапке появляется имя демо-координатора.
3. Координатор открывает подготовленный инцидент, выбирает допустимый новый статус и заполняет причину, если переход её требует.
4. АРМ сохраняет изменение через текущий API. На карточке виден новый статус, а в журнале — имя демо-координатора, действие и время. Ту же карточку можно открыть в мини-ITSM из этой сессии. Видеостена обновится через текущий опрос.
5. Через меню профиля ведущий нажимает «Выйти». Возвращается экран входа. Повторный показ начинается с той же формы.

Для репетиции заранее подготовить реквизиты для ведущего и инцидент с допустимым переходом. Если сценарий нужно показать повторно с исходным статусом, взять второй подготовленный инцидент или восстановить демо-набор перед показом.

## 2. Что меняется в текущем проекте

Сейчас стартовое окно «Начать смену» предлагает ввести имя. АРМ и мини-ITSM сохраняют его в браузере и передают в API в поле `by`. Оба экрана работают через один FastAPI и локальный JSON с инцидентами. [README](../README.md) · [Текущий контракт](contract.md) · [Решения по АРМ](decisions.md)

| Часть | Что сделать |
| --- | --- |
| Экран входа | Переиспользовать стартовое окно в `frontend/index.html`. Заменить поле имени на форму входа, добавить профиль и кнопку «Выйти» в шапке. |
| Клиент API | В `frontend/js/api.js` добавить вход, загрузку профиля и выход. Во всех запросах изменения убрать `by`. Обработку истёкшей сессии использовать в АРМ и мини-ITSM. |
| FastAPI | Добавить небольшой модуль, например `backend/app/auth.py`, с проверкой демо-учёток, хранением сессий, маршрутами входа и общей зависимостью для защищённых запросов. Подключить зависимость в `main.py`, `outage_api.py` и `feedback_api.py`. |
| Инциденты и журнал | Переиспользовать `backend/app/itsm.py`, текущие переходы статуса и проверку версии. Передавать в существующие операции имя из серверного профиля. |
| Мини-ITSM | В `frontend/itsm.html` заменить редактируемое поле имени на профиль из общей сессии. По прямой ссылке без сессии направлять на экран входа с возвратом к карточке. |
| Видеостена | Оставить открытие `/wall` без входа и существующий опрос снимка для синтетического демо-набора. Операции записи доступны только с сессией координатора. |

## 3. Демо-учётки и сессия

Демо-аккаунт задаётся на сервере. У него есть логин, пароль для показа, постоянный идентификатор и отображаемое имя. Пример логина — `demo.coordinator`, имя в интерфейсе — «Демо-координатор». Фактические реквизиты хранятся в конфигурации запуска и передаются ведущему отдельно. Для пароля в конфигурации достаточно хранить проверочный хеш. При двух аккаунтах каждому задаётся уникальное отображаемое имя, поскольку текущая модель журнала и владения использует имя.

После успешного входа сервер выдаёт случайный идентификатор сессии в cookie с `HttpOnly`, `SameSite=Lax` и `Path=/`. При HTTPS добавляется `Secure`. Сессии можно хранить в памяти одного процесса FastAPI, который уже используется в демо. Сессия действует до выхода, перезапуска сервера или истечения настроенного срока. Пароль из формы отправляется только в запросе входа и очищается после его обработки.

FastAPI при каждой записи определяет автора по сессии. На этом этапе профиль может передавать в существующий журнал и механику «Взять в работу» настроенное имя. Миграция старых записей и владения на идентификаторы для показа не требуется. Персональная очередь берёт имя из сессии, как и сохранение её настроек. Для запросов из браузера, меняющих состояние, сервер проверяет доверенный origin и использует один домен с фронтендом.

## 4. Контракт API

| Метод и маршрут | Поведение |
| --- | --- |
| `POST /api/auth/login` | Принимает `login` и `password`. При успехе создаёт сессию, ставит cookie и возвращает профиль `{id, login, display_name}`. Для неизвестного логина и ошибки пароля возвращает одинаковый `401` с сообщением «Неверный логин или пароль». |
| `GET /api/auth/me` | Возвращает профиль текущей сессии. Если сессии нет или срок истёк, возвращает `401`. АРМ вызывает маршрут при загрузке и перезагрузке. |
| `POST /api/auth/logout` | Удаляет серверную сессию, очищает cookie, возвращает `204`. |
| `POST /api/itsm/{id}/state` | Принимает текущие поля `state_id`, `reason`, `comment` и `expected_hash`. Автор берётся из сессии. Успех возвращает обновлённую карточку. Устаревшая версия возвращает `409`. |
| Защищённые маршруты | Требуют активную сессию. При её отсутствии возвращают `401` до чтения закрытой карточки или выполнения записи. |

Проверку сессии подключить ко всем операциям записи, включая смену статуса, назначение и перехват, комментарии, эскалацию, приоритет и срок, действия со сбоями и дублями, обратную связь ИИ, настройки очереди и импорт. Карточки, история, личная очередь и экспорт также требуют сессии. Общий демо-снимок остаётся доступен видеостене. Импорт и экспорт оставить в текущем меню только для вошедшего демо-координатора.

Переданное клиентом поле `by`, если его ещё отправляет старый фронтенд, не меняет автора. Новые запросы его не передают. После выхода прежняя cookie перестаёт работать даже при прямом запросе к API.

## 5. Интерфейс и состояния

| Состояние | Что видит пользователь |
| --- | --- |
| Первый запуск | Экран «Вход в АРМ координатора». Поля «Логин» и «Пароль», кнопка «Войти», короткая подпись «Демонстрационный доступ». Клавиша Enter отправляет форму. |
| Вход проверяется | Кнопка временно недоступна, на ней текст «Входим…». |
| Ошибка реквизитов | Сообщение «Неверный логин или пароль». Логин остаётся в поле, пароль очищается. При сбое связи показывается «Не удалось войти. Попробуйте ещё раз». |
| Есть сессия | Дашборд и имя в шапке. «Выйти» находится в меню профиля. Управление звуком и уведомлениями остаётся отдельным действием. |
| Открыта прямая ссылка | После входа открывается исходная карточка мини-ITSM. Для возврата принимаются только внутренние маршруты приложения. |
| Сессия закончилась | При `401` рабочие данные скрываются, форма сообщает «Войдите снова». После входа карточка загружается заново. Сохранение требует повторного подтверждения. |
| Изменение подтверждено | Карточка показывает новый статус и запись в журнале. При конфликте версия обновляется, координатор снова проверяет переход. |

В форме использовать явные подписи полей, видимый фокус с клавиатуры и сообщение об ошибке рядом с кнопкой. Использовать текущий фирменный стиль АРМ. Настройки темы, карточек и колонок можно брать из существующего профиля настроек, ключ которого связан с демо-координатором.

## 6. Порядок реализации

1. **Серверная основа.** Добавить демо-конфигурацию, сессии и три маршрута входа. Проверить корректные и ошибочные реквизиты и отзыв сессии после выхода.
2. **Основной экран.** Подключить форму, профиль и выход. Дашборд начинает загружать рабочие данные после успешной проверки профиля. Перезагрузка сохраняет вход, пока сессия действует.
3. **Первый сквозной сценарий.** Привязать смену статуса к сессии, проверить автора в журнале и открытие мини-ITSM. Подключить ту же проверку к остальным пишущим маршрутам и перевести личную очередь и настройки на подтверждённый профиль.
4. **Репетиция.** Запустить один процесс FastAPI на демо-данных, проверить АРМ и видеостену в разных окнах. Подготовить реквизиты и исходные карточки. До показа пройти список приёмки.

## 7. Приёмка перед показом

- [ ] Подготовленные реквизиты открывают АРМ под настроенным именем. С ошибочным паролем форма остаётся открытой.
- [ ] После обновления страницы сессия сохраняется. Прямая ссылка на мини-ITSM после входа возвращает к исходной карточке.
- [ ] Статус меняется в АРМ, совпадает с мини-ITSM, а журнал показывает демо-координатора. При устаревшей версии карточки доступно обновление перед повторным подтверждением.
- [ ] Прямой запрос на смену статуса без сессии получает `401`. Подстановка `by` не позволяет записать действие от другого имени.
- [ ] После выхода и при истечении сессии АРМ возвращает на вход. Видеостена продолжает показывать демо-поток.
- [ ] Если настроены две учётки, их имена различимы в журнале, а личные очереди и выбор «Мои» работают для каждого отдельно.

## 8. Когда понадобится реальная интеграция

При переходе к рабочим данным локальную проверку демо-учёток заменяет корпоративный SSO. АРМ сохраняет общий профиль и серверную проверку действий. Отдельно подтверждается поддерживаемый способ вызова API SimpleOne с правами конкретного сотрудника. До включения рабочей записи в тестовом контуре проверяются права на действие и автор в штатной истории SimpleOne.

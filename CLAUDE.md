# Дашборд координатора массовых инцидентов (хакатон МТС)

Веб-дашборд для отдела координации массовых инцидентов. Читает JSON-файл инцидентов
(формат МТС), раскладывает по 4 группам, оповещает о критических и о назначенных
на координаторов. На защите жюри **правит JSON-файл вживую** — дашборд должен реагировать
за ≤2 с и не падать на полузаписанном файле.

Как устроена работа (ответ менторов): **один большой экран (видеостена)** со всеми инцидентами,
под ним **рабочие места координаторов**, где они распределяют инциденты по командам.
Три экрана: `/wall` — видеостена (только просмотр), `/` — АРМ координатора, `/itsm/{id}` — мини-ITSM.

## Стек и запуск
- Backend: Python 3.11+ (у нас 3.14), FastAPI, один процесс.
- Frontend: **без сборки** — ES-модули + CSS в `frontend/`, их раздаёт FastAPI на том же порту. npm не нужен
  (на площадке не было интернета, и так надёжнее на защите). Шрифты МТС — `frontend/fonts/`.
- Установка: `python -m venv .venv && .venv/Scripts/pip install -r requirements.txt`
- Сервер: `.venv/Scripts/python -m uvicorn backend.app.main:app --port 8000 --reload`
- Тесты: `.venv/Scripts/python -m pytest backend/tests -q` (должны проходить перед каждым коммитом)
- АРМ: http://127.0.0.1:8000/ · стена: http://127.0.0.1:8000/wall · ITSM: http://127.0.0.1:8000/itsm/<id>
  (правки JS/CSS видны после перезагрузки страницы). Для АРМ на других ПК: `--host 0.0.0.0`.
- Демо: `.venv/Scripts/python scripts/demo.py list | step N | reset | reset demo | fresh`.
  `reset demo` — свой демо-файл (`scripts/make_demo.py`) со свежими датами.

## Где что лежит
- `data/original/` — оригиналы от организаторов, **не трогать**. `data/incidents.json` — рабочий файл, его и правят.
- `config/rules.yaml` — правила групп, статусы, приоритеты, команда координаторов.
- `backend/app/adapter.py` — чтение полей МТС → нормализованный Incident. `itsm.py` — запись (действия
  координатора → поля МТС в файле + наше поле `workLog`). Только эти два модуля знают формат файла.
- `backend/app/desk.py` — общее состояние смены: тревоги с «Принял» и «в работе у …» (`cache/desk_state.json`).
- `backend/app/groups.py` — группы. `diff.py` — события. `store.py` — опрос файла и снимок. `clock.py` — «сейчас».
- `backend/app/forecast.py` — прогноз нарушения срока (медиана по истории). `actions.py` — очередь «Что делать сейчас» + черновики.
- `frontend/js/`: `main.js` (АРМ), `wall.js` (стена), `desk.js` (диалоги передачи/эскалации), `render.js` (общая отрисовка),
  `alerts.js` (звук/голос по тревогам с сервера), `api.js` (опрос и действия), `sound.js`. `frontend/itsm.html` — мини-ITSM.
- `backend/app/ai/` — ИИ: правила `rules.py` (сейчас включены) и GigaChat `llm.py` (готов, но **выключен**: `LLM_PROVIDER=rules`).
- `docs/contract.md` — API и форма Incident для фронта. `docs/sample-snapshot.json` — живой пример ответа.
- `docs/data-report.md` — разведка данных.

## Правила домена (не нарушать)
- Статусы по `stateId`: 0 Назначен, 2 Выполняется — **активные**; 7 Завершен (Resolved) — решён, но может вернуться
  в работу; 10 Закрыт (Closed) — окончательно; 20 Исследование ситуации — решён, идёт разбор причин.
  В файле описания полей 7 и 10 перепутаны и 20 нет — верим данным и ответу менторов.
- Приоритет по `priorityId`: 4 Наивысший = **критический**, 3 Высокий.
- Группы: критические = prio 4 и активный (+решённый висит 30 мин с пометкой «решён»);
  на координаторах = команда «КЦ ИТ Координаторы Массовых Инцидентов» и статус 0/2/20;
  высокий = prio 3 и активный; исследование = статус 20. Инцидент может быть в нескольких группах.
- Даты в файле — ISO UTC с `Z`, бывают микросекунды и `null`. Выгрузка старая (8–11 ноября),
  поэтому по умолчанию `TIME_MODE=export`: «сейчас» = момент выгрузки + сколько прошло с запуска.
- Файл — единственный источник правды и «база инцидентов». БД нет. Действия из АРМ/ITSM пишутся в файл
  (атомарно, перечитав его прямо перед записью; битый файл — правка отклоняется с 409, файл жюри не трогаем).
- Переходы статусов — `transitions` в `rules.yaml` (свои правила разрешены менторами); 10 Закрыт — финальный.
  `completionDate` = время перевода в «Завершен», при возврате в работу очищается.
- Тревоги общие: эпизод = инцидент вошёл в «критические»/«на координаторах»; «Принял» на любом АРМ снимает баннер везде;
  повторный вход в группу — новый эпизод.
- `solution` бывает и у активных — показываем только у решённых.

## Как работаем
- Весь код пишет Claude; команда — вопросы менторам, проверка звука/вида на проекторе, коммиты, защита.
- Меняешь контракт — обнови `docs/contract.md` и `docs/sample-snapshot.json`, напиши в чат.
- Один срез = один коммит, тесты зелёные.
